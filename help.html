Proyecto

EasyPark valida una experiencia móvil para encontrar estacionamiento por destino, comparar alternativas y distinguir claramente entre reserva privada, estacionamiento urbano, orientación de parking tradicional/calle y Express simulado.

Resultado esperado: cualquier tester debe entender qué puede probar, qué es ficticio y qué etiqueta usar para reportar feedback.

Audiencias

  • Testers: recorren flujos y capturan evidencia.
  • Stakeholders: revisan alcance y riesgos.
  • Creadores: implementan cambios guiados por refs estables.

Roles y tipos de oferta

Conductor: busca, usa Copilot, paga con tarjeta ficticia y controla sesiones. Anfitrión: carga cocheras privadas para revisión. Operación: revisa publicaciones, incidentes y liquidaciones manuales.

  • Privada reservable: entra a checkout privado.
  • Urbana: zona/código/duración y sesión ordinaria.
  • Tradicional/calle: orientación sin checkout privado.
  • Express: barrera compatible ficticia separada de la reserva privada.

Arquitectura y límites

Todo corre localmente en HTML/CSS/JavaScript. No hay backend, LLM, pagos reales, SMS, cámara, operador, fiscalización ni integración municipal.

Prototipo público: usá solo datos ficticios. No ingreses tarjeta real, CVV, CBU/CVU, identificación fiscal, patente real, ubicación real, cámara ni credenciales.

La referencia pública de EasyPark España se usa solo como inspiración de patrones. No se copian textos, activos, marca visual ni trade dress.

Cómo probar

Preparación

  1. Abrí index.html en navegador moderno móvil o desktop responsive.
  2. Activá etiquetas si necesitás refs.
  3. Usá datos ficticios: TEST-123, alias demo y tarjetas de prueba predefinidas.

Reset local

Para empezar limpio, abrí la consola del navegador y ejecutá localStorage.clear(); luego recargá.

Evidencia útil

Capturá pantalla, ref visible, pasos, resultado esperado vs observado, navegador y tamaño de pantalla.

Inicio del prototipo y ayuda visible

Prerequisitos
Abrir index.html con etiquetas visibles si se necesita reportar feedback.
Pasos
Verificar APP-HOME-01, la guía REF-GUIDE-01, el enlace superior “Ayuda” y la tarjeta HELP-PORTAL-01.
Resultado esperado
El enlace de Ayuda abre este portal en help.html sin depender de JavaScript ni del wizard compacto heredado.
Refs relevantes
APP-HOME-01, REF-GUIDE-01, HELP-PORTAL-01.
Casos límite
Si se ocultan etiquetas, la navegación debe seguir funcionando y el enlace debe conservar destino local.

Orden sugerido

  1. Onboarding y cuenta.
  2. Conductor privado completo.
  3. Urbano ordinario y actividad.
  4. Copilot con refinamientos.
  5. Proveedor y operación.
  6. Express con consentimiento y fallback.
  7. Revisión responsive, teclado, foco visible y lectura de labels.
Supuesto de producción: lo que acá es local/ficticio necesitaría backend, validaciones, permisos y auditoría reales.

Onboarding

Alta guiada

Prerequisitos
Datos ficticios y código visible 2468.
Pasos
ONB-WELCOME-01 → ONB-ROLE-01 → ONB-VERIFY-01 → ONB-PROFILE-01 → ONB-SETUP-01 → ONB-PREFS-01 → ONB-DONE-01.
Resultado esperado
Guarda estado ficticio y deriva a conductor o anfitrión.
Casos límite
Código incorrecto bloquea avance.

Cuenta segura

Prerequisitos
Usar solo perfil, contacto, patente y comercio ficticios.
Pasos
ACCOUNT-HOME-01 → ACCOUNT-PROFILE-01 → ACCOUNT-VEHICLE-01 → ACCOUNT-PAYMENT-01 → ACCOUNT-PAYOUT-01 → ACCOUNT-BUSINESS-01 → ACCOUNT-PREFS-01 → ACCOUNT-SUMMARY-01.
Resultado esperado
Persiste solo perfil, preferencias y metadatos ficticios en localStorage.
Refs relevantes
ACCOUNT-PAYMENT-01, ACCOUNT-PAYOUT-01, ACCOUNT-SUMMARY-01.
Casos límite
No existen campos de PAN, CVV, vencimiento, CBU/CVU completo, identificación fiscal real, clave o secreto.

Conductor: cochera privada

Prerequisitos
Elegir “Cochera privada reservable”.
Pasos
DRV-START-01, DRV-TIME-01, DRV-RESULTS-01, DRV-DETAIL-01, DRV-PAYMENT-01, DRV-CONFIRM-01, DRV-RECEIPT-01, DRV-SESSION-01.
Resultado esperado
Solo una opción privada publicada entra a checkout; rechazo de pago o hold vencido bloquea recibo.
Edge cases
Parking tradicional/calle muestran orientación y vuelven a resultados.

Conductor: zona urbana

Prerequisitos
Elegir “Zona urbana o parking común”.
Pasos
DRV-ZONE-01, DRV-VEHICLE-01, DRV-DURATION-01, DRV-LIMIT-01, SESSION-ACTIVE-01.
Resultado esperado
Duración se clampa al máximo; sesión muestra operador/control ficticio SESSION-OPERATOR-01, alerta SESSION-ALERT-01, extensión SESSION-EXTEND-01 y fin temprano SESSION-END-01.
Edge cases
Extensión más allá del máximo queda bloqueada.

Actividad y recibos

Prerequisitos
Puede probarse sin sesiones o después de finalizar una sesión urbana/Express.
Pasos
ACTIVITY-HOME-01 → ACTIVITY-HISTORY-01 → ACTIVITY-RECEIPT-01.
Resultado esperado
Muestra sesión actual, historial local, estado de pago simulado y descarga de PDF simulada sin crear archivo real.
Refs relevantes
ACTIVITY-HOME-01, ACTIVITY-HISTORY-01, ACTIVITY-RECEIPT-01.
Casos límite
Con historial vacío muestra estado vacío útil; el guardado repetido de recibo Express debe ser idempotente y no duplicar movimientos.

Copilot

Prerequisitos
Entrar desde “Usar EasyPark Copilot”; voz depende del navegador.
Pasos
Usar texto/chips en AI-CHAT-01, probar voz en AI-VOICE-01, revisar AI-CONTEXT-01, itinerario, estrategias y handoff.
Resultado esperado
Deduce preferencias por reglas locales, permite editar contexto y deriva a detalle solo si la opción es reservable publicada.
Refs relevantes
AI-ENTRY-01, AI-CHAT-01, AI-VOICE-01, AI-CONTEXT-01, AI-STRATEGY-01, AI-HANDOFF-01.
Casos límite
Si SpeechRecognition no existe, debe explicar fallback a texto; opciones de orientación no entran a checkout; Copilot no reserva, no cobra y no emite recibos.

Anfitrión

Prerequisitos
Usar dirección, instrucciones y tarifa ficticias.
Pasos
PROV-LOCATION-01 → PROV-SPACE-01 → PROV-AVAIL-01 → PROV-TARIFF-01 → PROV-PAYMENT-01 → PROV-REVIEW-01.
Resultado esperado
Crea una cochera local para el ranking; queda publicada o pendiente según estado elegido; cobro y revisión son simulados.
Refs relevantes
PROV-LOCATION-01, PROV-TARIFF-01, PROV-REVIEW-01.
Casos límite
Estado pendiente debe aparecer en operación; textos de usuario se escapan antes de mostrarse para evitar HTML inyectado.

Operación

Prerequisitos
Puede probarse con o sin cocheras creadas por anfitrión.
Pasos
OPS-HOME-01 → OPS-PENDING-01 → OPS-INCIDENTS-01 → OPS-SETTLEMENTS-01.
Resultado esperado
Permite revisar colas, incidentes y liquidaciones ficticias en modo lectura/simulación.
Refs relevantes
OPS-PENDING-01, OPS-INCIDENTS-01, OPS-SETTLEMENTS-01.
Casos límite
Colas vacías deben explicar que no hay envíos; acciones son manuales/simuladas y no aprueban, liquidan ni notifican sistemas reales.

Express

Prerequisitos
Usar patente ficticia y sitio compatible ficticio.
Pasos
EXPRESS-HOME-01 → EXPRESS-CONSENT-01 → EXPRESS-ENTRY-01 → EXPRESS-SESSION-01 → EXPRESS-EXIT-01.
Resultado esperado
Simula entrada/salida, termina sesión y guarda recibo ficticio en actividad.
Refs relevantes
EXPRESS-CONSENT-01, EXPRESS-ENTRY-01, EXPRESS-SESSION-01, EXPRESS-EXIT-01.
Casos límite
Consentimiento sin marcar usa fallback manual; guardado repetido de recibo debe ser idempotente; no hay cámara, operador ni lectura real.

Para creadores: refs estables

Las etiquetas rojas tienen forma PREFIJO-AREA-01. Catálogo actual: APP/HOME, REF/HELP, ONB, ACCOUNT, DRV, SESSION, ACTIVITY, AI, PROV, OPS, EXPRESS.

Refs de entrada global: APP-HOME-01, REF-GUIDE-01, HELP-PORTAL-01.

Ejemplo: “Cambiar EXPRESS-CONSENT-01 para hacer más claro que no usa cámara real”.

Workflow de cambio

  1. Proponer con ref, problema y resultado esperado.
  2. Implementar en el archivo permitido.
  3. Verificar sintaxis, refs, límites de seguridad y flujos existentes.
  4. Actualizar README o ayuda si cambia comportamiento.
  5. Usar Git como fuente de verdad y Buzz para coordinación/ejecución.

Checklist para nueva pantalla

  • Agregar ref única y documentarla.
  • Mantener un CTA contextual por pantalla.
  • Escapar salida de usuario antes de insertarla.
  • No crear campos sensibles ni integraciones reales.
  • No permitir que Copilot/guía urbana/Express escriban verdad de reserva privada.
  • Ejecutar verificación y registrar riesgos.
